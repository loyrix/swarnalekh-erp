## Core Engineering Rules

1. Search before writing new logic. Reuse existing modules, services, widgets, and shared packages.
2. Tenant isolation is mandatory. Every tenant-owned database query must be scoped by `tenantId`.
3. Business calculations belong in `packages/business-logic/` when shared by API and Flutter.
4. Server-side calculations are the source of truth. Flutter may preview calculations, but persisted totals come from the API.
5. Use transactions for multi-table operations such as invoice creation and inventory status changes.
6. Keep modules aligned with the PDF flow. Do not add unrelated breadth.
7. Add tests for business logic and service behavior when adding or changing workflows.
8. Keep forms short, fast, and touch-friendly.

## Backend Rules

- NestJS remains the backend framework.
- Controllers handle HTTP concerns.
- Services own business behavior.
- Prisma handles persistence.
- DTOs validate incoming payloads.
- Use soft delete for business records where deletion would affect history.
- Billing mutations must update invoice history and inventory status atomically.
- Mortgage mutations must update payment history and loan balance atomically.
- Invoice numbers and mortgage receipt numbers must be generated by the server.

## Flutter Rules

- Use the existing Flutter app as the primary web/mobile UI.
- Use GoRouter for navigation.
- Use Riverpod or the existing local pattern for async state.
- Show loading, empty, and error states for operational screens.
- Keep primary navigation aligned to the PDF modules.
- Use tables/lists for inventory by default.
- Billing should make the selected product, weight, price, GST, payment method, and final total clear.
- Mortgage screens should make loan amount, interest, pending balance, due date, and receipt history clear.

## Required Test Discipline

For each PDF workflow added or changed, add focused tests where the risk lives:

- `packages/business-logic/` for pure calculations
- NestJS service tests for API workflows
- Flutter tests for key UI assumptions or provider behavior

Before committing, the tracked hook runs:

- Formatter checks
- Workspace tests
- Workspace builds
- Flutter analyzer
- Flutter tests
- Flutter web build
